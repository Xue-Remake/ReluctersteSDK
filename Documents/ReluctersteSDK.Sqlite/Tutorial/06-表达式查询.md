# 06 · 表达式查询

**目标**：把 `Where(r => …)` 的翻译规则、参数绑定和链式构建器用清楚；知道哪些表达式会走 SQL，哪些会被编译后在内存求值。

---

## 1. 基本形态

```csharp
using ReluctersteSDK.Sqlite.RowMod;

List<Row> rows = await users
    .Where(r => r.Get<int>("age") >= 18)
    .OrderByDescending("age")
    .Take(20)
    .ToListAsync();
```

`RowTable.Where(...)` 返回 `RowQuery`；`RowQuery` 的所有方法返回 `this`，可链式调用。

| 方法 | SQL 片段 |
|---|---|
| `Select(params string[] columns)` | `SELECT c1, c2`；不调用则 `*` |
| `Where(Expression<Func<Row,bool>>)` | `WHERE …`；多次调用用 `AND` 连接 |
| `OrderBy(string column)` | `ORDER BY "col" ASC` |
| `OrderByDescending(string column)` | `ORDER BY "col" DESC` |
| `Skip(int)` | `OFFSET n` |
| `Take(int)` | `LIMIT n` |
| `ToListAsync()` | `List<Row>` |
| `FirstOrDefaultAsync()` | `Row?` |
| `CountAsync()` | `long` |
| `DeleteAsync()` | `int` |
| `UpdateAsync(Row)` | `int` |

---

## 2. 支持的表达式

### 比较

```csharp
r.Get<int>("age") == 18
r.Get<int>("age") != 18
r.Get<int>("age") > 18
r.Get<int>("age") >= 18
r.Get<int>("age") < 18
r.Get<int>("age") <= 18
```

### 逻辑

```csharp
r.Get<int>("age") >= 18 && r.Get<int>("age") < 65
r.Get<string>("name") == "Alice" || r.Get<string>("name") == "Bob"
!(r.Get<int>("age") < 18)
```

翻译结果会自动加括号：

```sql
(("age" >= @p0) AND ("age" < @p1))
```

### 字符串

```csharp
r.Get<string>("email")!.Contains("example")
```

生成：

```sql
"email" LIKE @p0    -- @p0 = "%example%"
```

只支持 `Contains`，没有 `StartsWith` / `EndsWith` / `ToLower`。

### 常量与变量

```csharp
int min = 18;
string name = "Alice";

await users
    .Where(r => r.Get<int>("age") >= min && r.Get<string>("name") == name)
    .ToListAsync();
```

变量会被求值并绑定为参数（不是拼进 SQL）。

---

## 3. 列名写法

```csharp
r.Get<int>("age")     // 推荐
r["age"]              // 等价，走索引器
```

- 列名字符串**原样加引号后进 SQL**；
- 不校验列是否存在，拼错要到执行期才报 `SqliteException`；
- `Row` 的列名大小写不敏感，但这里生成的 SQL 标识符保留你写的原样。

---

## 4. 不支持 / 会退化的情况

| 表达式 | 行为 |
|---|---|
| `in` / `Contains` 集合 | 不支持；改用多个 `OR` 或原生 SQL |
| `StartsWith` / `EndsWith` | 不支持翻译；可能被编译求值 |
| 排序 lambda `OrderBy(r => …)` | 没有该重载，只能传列名 |
| `OR` 分组括号 | 表达式树本身有优先级，但不要依赖手写括号 |
| 方法调用（除 `Contains`） | 走 `Expression.Compile()` 求值 |
| 字符串插值 | 同上，可能整体被求值 |
| 引用 `Row` 实例成员 | 编译时可能直接抛异常 |

“走编译求值”意味着：

- 能跑通；
- 但结果只是作为一个**参数**传给 SQL；
- 过滤不在数据库端完成，可能变成全表扫描后内存筛选。

复杂条件直接写原生 SQL 更可靠：

```csharp
await db.QuerySqlAsync(
    "SELECT * FROM users WHERE age IN (@a, @b, @c)",
    r => r,
    new { a = 18, b = 21, c = 30 });
```

---

## 5. 构建器是可变对象

```csharp
RowQuery q = users.Where(r => r.Get<int>("age") >= 18);

List<Row> a = await q.ToListAsync();
List<Row> b = await q.Where(r => r.Get<string>("name") == "Alice").ToListAsync();
// 现在 q 也带上了 name 条件
```

`Where` 直接往内部列表追加，**不是不可变链**。需要复用基础条件时，自己重新 `users.Where(...)` 构建，或把条件合并成一个表达式。

```csharp
// ✅ 每次都从 table 重新开始
RowQuery Base() => users.Where(r => r.Get<int>("age") >= 18);

var list1 = await Base().ToListAsync();
var list2 = await Base().Where(r => r.Get<string>("name") == "Alice").ToListAsync();
```

### `FirstOrDefaultAsync` 会改 `_limit`

```csharp
RowQuery q = users.Where(r => r.Get<int>("age") >= 18);
Row? one = await q.FirstOrDefaultAsync();   // 内部 _limit = 1
List<Row> many = await q.ToListAsync();      // 仍然 LIMIT 1
```

一次性使用没问题；要复用就重新构建。

## 6. 分页

```csharp
int pageSize = 20;
int page = 3;

List<Row> rows = await users
    .Where(r => r.Get<int>("is_active") == 1)
    .OrderBy("id")
    .Skip((page - 1) * pageSize)
    .Take(pageSize)
    .ToListAsync();
```

- 只 `Skip` 不 `Take`：生成 `LIMIT -1 OFFSET n`；
- `Skip` 负数没有校验，会生成 `OFFSET -n`，SQLite 行为未定义——自己保证非负；
- 没有 `OrderBy` 时分页结果不稳定。

---

## 7. 统计、删除、更新

```csharp
// 统计
long adults = await users
    .Where(r => r.Get<int>("age") >= 18)
    .CountAsync();

// 删除（返回受影响行数）
int deleted = await users
    .Where(r => r.Get<int>("is_active") == 0)
    .DeleteAsync();

// 更新（只改给定列）
int updated = await users
    .Where(r => r.Get<string>("name") == "Alice")
    .UpdateAsync(new Row { ["age"] = 26, ["is_active"] = 1 });
```

`CountAsync` / `DeleteAsync` / `UpdateAsync` 都复用 `_whereClauses` 与参数表，但**不会**使用 `Skip` / `Take`：

- `CountAsync` 生成 `SELECT COUNT(*) … WHERE …`；
- `DeleteAsync` 生成 `DELETE … WHERE …`；
- `UpdateAsync` 在 WHERE 参数之后追加 SET 参数。

## 8. 完整示例

```csharp
using ReluctersteSDK.Sqlite;
using ReluctersteSDK.Sqlite.RowMod;

await using var db = new SqliteDataBase(folder, "expr.db");
await db.EnsureInitializedAsync();
await using var ctx = new RowDbContext(db);

RowTable users = ctx["users"];
await users.CreateTableIfNotExistsAsync(
    ("id", "INTEGER PRIMARY KEY AUTOINCREMENT"),
    ("name", "TEXT NOT NULL"),
    ("age", "INTEGER"),
    ("email", "TEXT"));

await users.AddRangeAsync(new[]
{
    new Row { ["name"] = "Alice", ["age"] = 25, ["email"] = "alice@gmail.com" },
    new Row { ["name"] = "Bob",   ["age"] = 17, ["email"] = "bob@example.com" },
    new Row { ["name"] = "Carol", ["age"] = 31, ["email"] = "carol@gmail.com" }
});

int minAge = 18;

List<Row> picked = await users
    .Where(r => r.Get<int>("age") >= minAge && r.Get<string>("email")!.Contains("gmail"))
    .OrderByDescending("age")
    .Take(10)
    .ToListAsync();

foreach (Row row in picked)
    Console.WriteLine($"{row.Get<string>("name")} / {row.Get<int>("age")}");
```

---

## 9. 限制清单

- 没有 `JOIN` / 子查询 / `GROUP BY` / `HAVING`；
- 没有 `IN`、`BETWEEN`、`LIKE` 直接构造（只能用 `Contains`）；
- 排序只能按列名，不能按表达式；
- 列名不校验；
- 构建器可变，复用要小心；
- 不支持的表达式会退化为内存求值。

需要上述任何一项，直接用 `db.QuerySqlAsync`。
