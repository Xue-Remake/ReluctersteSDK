# 09 · 常见问题与排错

**目标**：把最常见的异常、静默失败与“为什么没按预期工作”集中成一张排查表。

---

## 1. 异常对照表

| 异常 / 消息 | 原因 | 处理 |
|---|---|---|
| `InvalidOperationException: Type X does not contain any [DbKey] or [DbColumn] property` | 实体没有映射特性 | 给属性加 `[DbKey]` / `[DbColumn]` |
| `InvalidOperationException: … does not define any [DbKey]` | `Upsert` / `Update` / `Delete` 需要主键 | 加 `[DbKey]` |
| `ArgumentException: Key count mismatch` | `GetByKeyAsync` / `DeleteByKeyAsync` 键数量不对 | 参数个数 = `[DbKey]` 属性数，顺序一致 |
| `NotSupportedException`（建表阶段） | 属性类型不在支持列表 | 改用基础类型，或自行序列化成 `string` / `byte[]` |
| `SqliteException: SQLite Error 1: 'no such table: X'` | 没建表 | 先 `EnsureTableAsync<T>()`；RowMod 先 `CreateTableIfNotExistsAsync` |
| `SQLite Error 1: 'no such column: X'` | 列名拼错 / 迁移没执行 | 对照特性与迁移；RowMod 表达式列名不校验 |
| `SQLite Error 19: 'UNIQUE constraint failed'` | 主键或唯一索引冲突 | 改用 `UpsertAsync`，或先查再插 |
| `SQLite Error 19: 'NOT NULL constraint failed'` | 不可空列传了 `null` | 给值或改成 `Nullable<T>` |
| `SQLite Error 5: 'database is locked'` | 写锁等待超过 `busy_timeout` | 缩短事务、减少并发写、启动早期跑迁移 |
| `SQLite Error 1: 'Cannot add a NOT NULL column with default value NULL'` | 加 `NOT NULL` 列没给默认值 | `defaultValueSql: "0"` 等 |
| `ObjectDisposedException` | 对已释放的 `SqliteDataBase` 写 | 检查 `await using` 作用域 |
| `JsonException`（Config 场景） | 配置 JSON 损坏 | 删除/修复文件；见 Config 文档 |

## 2. “没报错但结果不对”

### 查询返回空

按顺序检查：

1. 表里真的有数据？`SELECT COUNT(*)`；
2. `where` 参数名与 `parameters` 属性名一致？大小写敏感；
3. 参数值类型是否被转换（`DateTime` 存的是 `"O"` 文本，比较时也用 `DateTime` 参数）；
4. 是否忘了 `ORDER BY` 导致看起来顺序不对；
5. RowMod 表达式列名拼错——不会报错，只会匹配不到。

```csharp
object? count = await db.ExecuteScalarAsync("SELECT COUNT(*) FROM players");
Console.WriteLine(count);
```

### `UpdateAsync` 把别的列清空了

`UpdateAsync<T>(entity)` 更新**全部非键列**，没赋值的属性会写成 `default`：

```csharp
// ❌ 只想改 score，结果 name / created_at 被写成默认值
await db.UpdateAsync(new PlayerRow { Id = 1, Score = 99 });

// ✅ 先读整行再改
PlayerRow row = (await db.GetByKeyAsync<PlayerRow>(1))!;
row.Score = 99;
await db.UpdateAsync(row);

// ✅ 或只改一列
await db.ExecuteAsync("UPDATE players SET score = @s WHERE id = @id", new { s = 99, id = 1 });
```

### `Upsert` 后其他列变默认值

`UpsertAsync` 同样要求传完整实体；它只保证“冲突时更新非键列”，不保证未赋值属性保持原值。

### `GetAllAsync` 很慢

它会把整表读进 `List<T>`。大表用 `QueryAsync` + `limit`，或 `QuerySqlAsync` 投影。

### RowMod 的 `Where` 没过滤

不支持的表达式会 `Compile()` 后在内存求值，结果作为参数绑定，**SQL 端不过滤**。检查表达式是否只用了：

- 比较运算；
- `&&` / `||` / `!`；
- `r.Get<T>("col")` / `r["col"]`；
- `string.Contains`。

其余请写原生 SQL。

## 3. 生命周期问题

### `ObjectDisposedException`

```csharp
// ❌ db 已被释放
await using (var db = new SqliteDataBase(folder, "app.db"))
{
    await db.EnsureInitializedAsync();
}

await db.ExecuteAsync("…");   // 抛异常
```

`RowDbContext` 会连带释放底层库：

```csharp
// ❌ 两个都 await using
await using var db = new SqliteDataBase(folder, "app.db");
await using var ctx = new RowDbContext(db);

// ✅ 只释放 ctx
await using var ctx = new RowDbContext(new SqliteDataBase(folder, "app.db"));
```

### 文件被占用 / 删不掉

SQLite 的连接是短连接，正常释放后文件可删。若删不掉：

- 确认没有其它进程打开；
- 检查是否有未 `await using` 的 `RowDbContext`；
- WAL 模式会留下 `-wal` / `-shm` 文件，关闭所有连接后会清理。

## 4. 迁移问题

### `InvalidOperationException: out-of-order migration`

已执行版本 1、3，又补了 2。执行器拒绝乱序。

处理：

- 新迁移用更大的版本号（4）；
- 或在开发环境删库重跑（会丢数据）。

### `NotSupportedException: Migration X does not define DownAsync`

该迁移不可回滚。生产环境建议每个迁移都写 `down`。

### 迁移执行到一半失败

每个迁移独立事务，失败的那个整体回滚，**不会写历史**。前面的迁移已提交，不会回滚。修正失败迁移后重新运行，会从失败的那个版本继续。

### 迁移后表结构没变

- 迁移没被调用（检查启动路径）；
- 版本号已记录，但 `UpAsync` 逻辑是空操作；
- 迁移写的是另一个库文件（路径不一致）。

## 5. 类型与格式

### `DateTime` 读回来 Kind 不对

存储是 `"O"` 往返格式，包含 `Kind`。写入 `DateTime.UtcNow`，读回是 `Utc`；写入 `DateTime.Now`，读回是 `Local`。跨时区比较前先统一成 UTC。

### `bool` 存成了 0/1

设计如此。查询时用 `== 1` / `== 0`，或用 `Row.Get<bool>`。

### 枚举

按底层整数存储。改枚举成员的值会让旧数据语义改变；需要稳定时显式指定数值。

### `decimal`

映射为 `REAL`，有精度损失风险；金额场景建议存 `long`（最小货币单位）或 `TEXT`。

## 6. 选择模式

| 需求 | 选择 |
|---|---|
| 固定实体、强类型 | 特性映射 |
| 运行期才知道表结构 | RowMod |
| 一次性导入/导出 | RowMod 或原生 SQL |
| 复杂 JOIN / 聚合 | 原生 SQL |
| 跨多次写要原子 | 迁移上下文，或单条 SQL |
| 结构演进 | 迁移 |
| 配置存储 | `ReluctersteSDK.Config` 的 `SqliteConfigStore<T>` |

---

## 7. 排查清单

1. 表建了吗？`EnsureTableAsync` / `CreateTableIfNotExistsAsync` / 迁移；
2. 列名对吗？特性 vs 实际表结构；
3. 主键顺序对吗？
4. 参数名对吗？大小写、`@` 前缀（库会补）；
5. 实体有公共无参构造函数吗？（`QueryAsync<T>` 的 `where T : new()`）
6. 类型在支持列表里吗？
7. 是不是在 `UpdateAsync` 里漏赋值，导致整列被覆盖？
8. 读操作是不是没等写操作完成？（并发时写锁只保护写）
9. 迁移版本是否乱序？
10. 数据库路径是不是另一个文件？

---

## 8. 限制速查

| 限制 | 影响的 API |
|---|---|
| 无公开事务 | 特性映射 CRUD、`ExecuteAsync` |
| 无 `CancellationToken` | 全部 CRUD |
| 无连接池 | 全部 |
| 写操作全局串行 | 全部写 |
| 迁移不做结构 diff | 迁移 |
| 不支持复杂类型 | 建表 |
| RowMod 无 JOIN / 子查询 / 分组 | `RowQuery` |
| RowMod 表达式列名不校验 | `Where` |
| `RowQuery` 可变 | 复用同一实例 |
| `RowDbContext.DisposeAsync` 连带释放 | 生命周期 |
