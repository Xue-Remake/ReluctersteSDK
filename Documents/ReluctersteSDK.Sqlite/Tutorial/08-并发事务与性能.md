# 08 · 并发、事务与性能

**目标**：知道写操作为什么排队、读操作为什么能并发、批量写入怎么选，以及 `SQLITE_BUSY` 出现时该往哪里调。

---

## 1. 连接模型

`SqliteDataBase` 不维护长连接。每次操作：

```
OpenConnectionAsync()
├─ EnsureInitializedAsync()（幂等，只真正初始化一次）
├─ new SqliteConnection(connectionString)
├─ OpenAsync()
├─ PRAGMA busy_timeout = 5000
├─ PRAGMA foreign_keys = ON
└─ 执行完 await using 释放
```

连接串固定：

```
Data Source = {DatabasePath}
Cache       = Shared
Mode        = ReadWriteCreate
```

**不能自定义连接串**，也没有连接池。这是小型本地库的取舍：避免长连接跨线程、WAL 生命周期与释放顺序问题。

---

## 2. 写操作串行化

所有写路径经过同一个 `SemaphoreSlim(1,1)`：

| 操作 | 走写锁 |
|---|---|
| `InsertAsync` / `UpsertAsync` / `UpdateAsync` / `DeleteAsync` / `DeleteByKeyAsync` | ✅ |
| `EnsureTableAsync` | ✅ |
| `ExecuteAsync` | ✅ |
| `RowTable.AddAsync` / `AddRangeAsync` | ✅ |
| `RowQuery.UpdateAsync` / `DeleteAsync` | ✅ |
| 迁移 `MigrateAsync` / `RollbackAsync` | ✅（整个迁移过程） |
| `QueryAsync` / `GetByKeyAsync` / `QuerySqlAsync` / `ExecuteScalarAsync` | ❌ |

含义：

- 多个线程同时写：排队执行，不会互相踩；
- 写与读：读不加锁，依赖 WAL + `busy_timeout`；
- **迁移期间所有写操作等待**，大表重建会明显阻塞。

---

## 3. 读并发示例

```csharp
using ReluctersteSDK.Sqlite;

await using var db = new SqliteDataBase(folder, "concurrent.db");
await db.EnsureInitializedAsync();
await db.EnsureTableAsync<PlayerRow>();

// 先写一些数据
for (int i = 1; i <= 100; i++)
    await db.InsertAsync(new PlayerRow { Id = i, Name = $"P{i}", Score = i });

// 并发读：都不加锁
Task<List<PlayerRow>>[] reads = Enumerable.Range(0, 8)
    .Select(_ => Task.Run(() => db.GetAllAsync<PlayerRow>()))
    .ToArray();

List<PlayerRow>[] results = await Task.WhenAll(reads);
Console.WriteLine(results.All(r => r.Count == 100));   // True
```

并发写同样安全，但会串行：

```csharp
Task[] writes = Enumerable.Range(200, 100)
    .Select(i => db.InsertAsync(new PlayerRow { Id = i, Name = $"W{i}", Score = i }))
    .ToArray();

await Task.WhenAll(writes);   // 内部排队，不会 SQLITE_BUSY（除非超过 busy_timeout）
```

## 4. 批量写入怎么选

| 方式 | 事务 | 连接次数 | 适用 |
|---|---|---|---|
| 循环 `InsertAsync` | 每条独立 | N | 少量数据、逻辑简单 |
| `ExecuteAsync` 拼多 VALUES | 一条语句 | 1 | 中等批量、能自己编号参数 |
| `RowTable.AddRangeAsync` | **单事务** | 1 | 大批量、允许用 RowMod |
| 迁移上下文 | 单事务 | 1 | 结构变更 + 数据迁移一起做 |

### `AddRangeAsync` 示例

```csharp
using ReluctersteSDK.Sqlite.RowMod;

await using var ctx = new RowDbContext(db);
RowTable table = ctx["players"];

await table.CreateTableIfNotExistsAsync(
    ("id", "INTEGER PRIMARY KEY"),
    ("name", "TEXT"),
    ("score", "INTEGER"));

Row[] rows = Enumerable.Range(1, 1000)
    .Select(i => new Row
    {
        ["id"] = i,
        ["name"] = $"P{i}",
        ["score"] = i % 100
    })
    .ToArray();

await table.AddRangeAsync(rows);   // 一个事务，失败整体回滚
```

### 多 VALUES 示例

```csharp
var parameters = new Dictionary<string, object?>();
var values = new List<string>();

for (int i = 0; i < 100; i++)
{
    values.Add($"(@id{i}, @name{i}, @score{i})");
    parameters[$"id{i}"] = i;
    parameters[$"name{i}"] = $"P{i}";
    parameters[$"score{i}"] = i;
}

await db.ExecuteAsync(
    $"INSERT INTO players (id, name, score) VALUES {string.Join(", ", values)};",
    parameters);
```

> 单条 SQL 的参数上限与 SQLite 编译选项有关（常见 999 / 32766）。大批量请分块。

## 5. 事务边界

当前版本**没有公开事务 API**。能获得原子性的地方只有：

1. `RowTable.AddRangeAsync`（仅插入）；
2. 迁移上下文（`SqliteMigrationContext` 的所有命令挂在同一事务）；
3. 单条 SQL 本身。

```csharp
// ❌ 不是原子操作
await db.ExecuteAsync("UPDATE accounts SET balance = balance - 100 WHERE id = 1");
await db.ExecuteAsync("UPDATE accounts SET balance = balance + 100 WHERE id = 2");
```

需要“扣款 + 入账”原子完成时：

- 用一条 `UPDATE … CASE`；
- 或写一个一次性迁移/维护脚本，用迁移上下文执行；
- 或等后续版本暴露事务 API（见 `Documents/待修问题清单.md` #14）。

## 6. WAL 与 `busy_timeout`

`EnsureInitializedAsync` 设置：

```sql
PRAGMA busy_timeout = 5000;
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;       -- enableWal: true（默认）
PRAGMA synchronous = NORMAL;     -- enableWal: true
```

| 项 | 作用 |
|---|---|
| WAL | 读写并行；写者不阻塞读者 |
| `busy_timeout=5000` | 遇到锁时最多等 5 秒，然后抛 `SQLITE_BUSY` |
| `synchronous=NORMAL` | WAL 下兼顾安全与吞吐；断电可能丢最后几条事务 |
| `foreign_keys=ON` | 每个连接都设置 |

关闭 WAL：

```csharp
var db = new SqliteDataBase(folder, "app.db", enableWal: false);
```

单写多读的桌面应用一般不需要关。

## 7. `SQLITE_BUSY` 排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 偶发 `database is locked` | 另一个进程持有写锁超过 5 秒 | 缩短事务；避免长迁移与大表重建 |
| 迁移时全部写操作卡住 | 迁移整体持写锁 | 把大迁移拆小；在启动早期执行 |
| 并发写偶尔超时 | 写入量超过单写者吞吐 | 批量写；减少写次数；考虑内存队列合并 |
| 读也报锁 | 非 WAL 模式，或外部进程独占 | 确认 `journal_mode=WAL`；避免 `Mode=ReadWrite` 独占 |

库本身**不重试**：`busy_timeout` 到点就抛。需要重试请在调用方包一层。

## 8. 性能清单

1. **减少连接次数**：批量插入用 `AddRangeAsync` 或多 VALUES；
2. **减少写锁持有时间**：不要在写操作之间夹业务计算；
3. **查询走索引**：给常用 `WHERE` / `ORDER BY` 列建索引（迁移里用 `CreateIndexAsync`）；
4. **避免 `SELECT *` 大表全读**：用 `limit` 或 `QuerySqlAsync` 只取需要的列；
5. **RowMod 表达式别退化**：不支持的条件会被编译后当参数，等于全表扫描；
6. **迁移放在启动早期**：避免运行中长时间阻塞写；
7. **`GetAllAsync` 只用于小表**；大表分页或投影；
8. **统计**：`Stopwatch` 包住关键路径，先量再优化。

## 9. 完整示例：并发写 + 批量读

```csharp
using System.Diagnostics;
using ReluctersteSDK.Sqlite;
using ReluctersteSDK.Sqlite.RowMod;

await using var db = new SqliteDataBase(folder, "perf.db");
await db.EnsureInitializedAsync();
await using var ctx = new RowDbContext(db);

RowTable table = ctx["items"];
await table.CreateTableIfNotExistsAsync(
    ("id", "INTEGER PRIMARY KEY"),
    ("payload", "TEXT"));

// 批量写
var sw = Stopwatch.StartNew();

Row[] rows = Enumerable.Range(1, 5000)
    .Select(i => new Row { ["id"] = i, ["payload"] = new string('x', 64) })
    .ToArray();

await table.AddRangeAsync(rows);
sw.Stop();
Console.WriteLine($"批量写入 5000 行：{sw.ElapsedMilliseconds} ms");

// 并发读
sw.Restart();
Task<long>[] counts = Enumerable.Range(0, 8)
    .Select(_ => Task.Run(() => table.CountAsync()))
    .ToArray();

long[] results = await Task.WhenAll(counts);
sw.Stop();

Console.WriteLine($"8 路并发计数：{sw.ElapsedMilliseconds} ms，结果 {results[0]}");
```

## 10. 限制

- 没有公开事务 API；
- 没有连接池；
- 没有重试；
- 写操作全局串行；
- 迁移整体持写锁；
- `QueryAsync` 会把整表结果读进 `List<T>`，没有流式 API。
