# 12 · 调试与统计

**目标**：不接调试器也能看清“实体多少、组件多少、哪个系统慢、事件有没有积压”，以及用控制台日志观察事件流。

---

## 1. 打开统计

```csharp
world.StatisticsEnabled = true;
```

默认关闭，避免常态 `Stopwatch` 开销。打开后：

- `World.Update` / `World.Render` 记录总耗时；
- 每个系统执行后记录 `SystemTiming`；
- `SystemTimings` 每次 `Update` 开头清空，保存上一帧结果。

---

## 2. 世界概览

```csharp
WorldStats stats = world.GetStats();

Console.WriteLine($"实体 {stats.EntityCount} / 槽位 {stats.EntityCapacity}");
Console.WriteLine($"组件类型 {stats.ComponentStoreCount}，实例 {stats.ComponentCount}");
Console.WriteLine($"系统 Update={stats.UpdateSystemCount} " +
                  $"LateUpdate={stats.LateUpdateSystemCount} " +
                  $"Render={stats.RenderSystemCount}");
Console.WriteLine($"帧号 {stats.FrameCount}，结构版本 {stats.StructuralVersion}");
Console.WriteLine($"Update {stats.UpdateMilliseconds:F3} ms，Render {stats.RenderMilliseconds:F3} ms");
Console.WriteLine($"事件队列 {stats.EventQueueCount}，待交换 {stats.PendingEventCount}");
```

| 字段 | 含义 |
|---|---|
| `EntityCount` / `EntityCapacity` | 存活实体 / 已分配槽位 |
| `ComponentStoreCount` / `ComponentCount` | 组件类型数 / 组件实例总数 |
| `UpdateSystemCount` / `LateUpdateSystemCount` / `RenderSystemCount` | 各阶段系统数 |
| `StructuralVersion` | 结构修改版本；持续增长说明每帧都在增删 |
| `FrameCount` | 已执行 Update 次数 |
| `UpdateMilliseconds` / `RenderMilliseconds` | 上一帧总耗时 |
| `IsDisposed` | 是否已释放 |
| `EventQueueCount` / `PendingEventCount` | 事件队列数 / 未交换事件数 |

## 3. 哪个系统慢

```csharp
foreach (SystemTiming timing in world.SystemTimings)
{
    Console.WriteLine($"{timing.Phase,-10} {timing.Milliseconds,7:F3} ms  {timing.SystemName}");
}
```

输出示例：

```
Update       0.042 ms  ReluctersteSDK.Game.Systems.MotionSystem
Update       0.118 ms  ReluctersteSDK.Game.Systems.TransformSystem
Update       0.007 ms  MyGame.PlayerAnimationSystem
Render       0.031 ms  ReluctersteSDK.Game.Rendering.SpriteRenderSystem
```

排查顺序：

1. 先看总耗时是否超过帧预算（60 FPS ≈ 16.7 ms）；
2. 再看单项占比；
3. 常见热点：`TransformSystem` 全量重算、`SpriteRenderSystem` 收集大量精灵、业务系统的 `Query.ForEach` 嵌套。

---

## 4. 组件分布

```csharp
foreach (ComponentStoreStats item in world.GetComponentStats())
{
    Console.WriteLine($"{item.ComponentType.Name,-20} {item.Count}");
}
```

适合发现：

- 某个组件数量远高于实体数（重复添加？）；
- 某个存储永远为空（`Without<T>` 调用时创建了空存储，不是 bug）。

## 5. 运行时覆盖层

把统计打印限制在每秒一次，避免刷屏：

```csharp
public sealed class StatsOverlaySystem : ISystem
{
    private float _timer;

    public void Execute(World world, float deltaTime)
    {
        _timer += deltaTime;
        if (_timer < 1f)
            return;

        _timer = 0f;
        WorldStats s = world.GetStats();

        Console.WriteLine(
            $"[{s.FrameCount}] entities={s.EntityCount} " +
            $"components={s.ComponentCount} " +
            $"update={s.UpdateMilliseconds:F2}ms " +
            $"render={s.RenderMilliseconds:F2}ms " +
            $"events={s.PendingEventCount}");

        foreach (SystemTiming t in world.SystemTimings)
        {
            if (t.Milliseconds > 1.0)
                Console.WriteLine($"  slow: {t.SystemName} {t.Milliseconds:F2} ms");
        }
    }
}

world.StatisticsEnabled = true;
world.AddSystem(new StatsOverlaySystem(), SystemPhase.LateUpdate);
```

## 6. 控制台事件日志

`EventLogger` 与 ECS 无关，只是带时间戳与彩色标签的控制台输出，适合调试期观察事件流。

```csharp
using ReluctersteSDK.Game;

[LogEvent("COMBAT")]
public sealed class EnemyKilledEvent
{
    public string EnemyId { get; init; } = "";
}

[LogEvent("SAVE")]
public sealed class SaveCompletedEvent
{
    public int Slot { get; init; }
}

EventLogger.Emit(new EnemyKilledEvent { EnemyId = "zombie-01" }, "僵尸被杀");
// [12:34:56.789] [COMBAT] 僵尸被杀

EventLogger.LogMarked("SAVE", "存档写入完成", ConsoleColor.Green);
// [12:34:56.790] [SAVE] 存档写入完成
```

规则：

- `Emit<T>` 读 `typeof(T)` 上的 `[LogEvent]`；**没有特性就什么都不输出**；
- 标签区分大小写，`Inherited = false`，派生类不继承标签；
- `LogMarked` 不需要类型，直接指定标签与颜色。

### 与 ECS 事件结合

```csharp
[LogEvent("DMG")]
public readonly record struct DamageDealt(Entity Attacker, Entity Target, int Amount);

// 在消费系统里
foreach (ref readonly DamageDealt e in world.Events.Read<DamageDealt>())
{
    EventLogger.Emit(e, $"{e.Attacker} → {e.Target} 造成 {e.Amount} 点伤害");
}
```

注意 `Emit<T>` 的 `T` 是**编译期静态类型**；把派生类赋给基类变量再调用，读的是基类的特性。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| 统计基于 `Stopwatch` | 只用于诊断，不保证跨平台精度 |
| 开启统计有小额分配 | 生产环境按需开启，或只在调试构建启用 |
| `SystemTimings` 只保留上一帧 | 需要历史数据请自己采样 |
| `EventLogger` 直接写 `Console` | 被重定向 / 被 UI 接管时不可用 |
| 无日志级别 | 不能按 Debug/Info/Error 过滤 |
| `Emit` 走反射查特性 | 每帧上千条会明显拖慢 |
| `EventLogger` 非线程安全 | 多线程同时改颜色会串位 |

---

## 8. 调试清单

出现问题时按这个顺序看：

1. `stats.EntityCount` 是否符合预期（实体泄漏？）；
2. `stats.StructuralVersion` 是否每帧都涨（在系统里反复 Add/Remove？）；
3. `stats.PendingEventCount` 是否持续增长（只有 Raise 没有 Read？）；
4. `SystemTimings` 里哪一项超过 1 ms；
5. `GetComponentStats()` 是否有意外为空的存储；
6. 最后才上断点或 `EventLogger`。
