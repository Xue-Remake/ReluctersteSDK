# 09 · 双缓冲事件

**目标**：让战斗系统把“造成伤害”交给死亡系统处理，而不在遍历中直接改结构；并理解“本帧登记、下帧可读”的时序。

---

## 1. 定义事件

用 `readonly record struct`，零分配：

```csharp
using ReluctersteSDK.Game.Ecs;

public readonly record struct DamageDealt(Entity Attacker, Entity Target, int Amount);
public readonly record struct EntityDied(Entity Victim, Entity Killer);
```

不需要继承基类，也没有注册步骤——**事件类型就是队列**。

---

## 2. 产生与消费

### 战斗系统

```csharp
public struct AttackTarget { public Entity Value; }
public struct AttackCooldown { public float Remaining; }

public sealed class CombatSystem : ISystem
{
    public void Execute(World world, float deltaTime)
    {
        world.Query<Health, AttackTarget, AttackCooldown>().ForEach(
            (Entity attacker, ref Health hp, ref AttackTarget target, ref AttackCooldown cd) =>
            {
                cd.Remaining -= deltaTime;
                if (cd.Remaining > 0f || !world.IsAlive(target.Value))
                    return;

                cd.Remaining = 0.8f;

                ref Health victim = ref world.Get<Health>(target.Value);
                int dealt = Math.Min(hp.Value / 10, victim.Value);
                victim.Value -= dealt;

                world.Events.Raise(new DamageDealt(attacker, target.Value, dealt));
            });
    }
}
```

### 死亡系统（下一帧）

```csharp
public struct Dead { }

public sealed class DeathSystem : ISystem
{
    public void Execute(World world, float deltaTime)
    {
        foreach (ref readonly DamageDealt e in world.Events.Read<DamageDealt>())
        {
            if (!world.IsAlive(e.Target))
                continue;

            ref Health hp = ref world.Get<Health>(e.Target);
            if (hp.Value > 0)
                continue;

            world.Commands.Add(e.Target, new Dead());
            world.Commands.Destroy(e.Target);
            world.Events.Raise(new EntityDied(e.Target, e.Attacker));
        }
    }
}
```

要点：

- `Read<T>()` 返回 `ReadOnlySpan<T>`，用 `foreach (ref readonly …)` 遍历；
- 遍历读缓冲时可以继续 `Raise`（写的是另一个列表）；
- 结构修改仍走 `Commands`，时序更可控。

## 3. 时序：第 N 帧写，第 N+1 帧读

`World.Update` 的顺序：

```
EnsureNotDisposed()
StartIfNeeded()          ← 首次会跑 Start + Startup
Events.Swap()            ← 交换读写缓冲
Update 阶段
LateUpdate 阶段
Commands.Playback()
```

所以：

| 登记位置 | 何时可读 |
|---|---|
| `Update` / `LateUpdate` / `Render` 期间 | 下一次 `Update` 开头交换之后（延迟 1 帧） |
| `Startup` 阶段 | 首帧即可读（`Swap` 发生在 Startup 之后） |
| `World.Update` 之外（UI 回调等） | 下一次 `Update` 开始时 |

所有阶段看到的是**同一份读缓冲**，不存在“Update 看不到、Render 看得到”。

## 4. `Read` 与 `ReadList`

```csharp
// span：零分配，适合热路径 / 需要 ref readonly
foreach (ref readonly DamageDealt e in world.Events.Read<DamageDealt>())
    …

// IReadOnlyList：零分配，可以存局部变量、传给方法
IReadOnlyList<DamageDealt> list = world.Events.ReadList<DamageDealt>();
Process(list);
```

| | `Read` | `ReadList` |
|---|---|---|
| 分配 | 0 | 0 |
| `ref readonly` 遍历 | ✅ | ❌ |
| 可传给别的方法 | ⚠️ 只能短时使用 | ✅ |
| 下一次 `Swap` 后 | span 失效 | 旧引用被清空（不崩，内容消失） |

`ReadList` 不是“安全版”，只是“不会变成野指针版”。需要跨帧保存必须自己 `ToArray()`。

## 5. 热路径：缓存队列

每帧上千次 `Raise` 时，避免每次做类型表查找：

```csharp
public sealed class BulletSystem : ISystem
{
    private EventQueue<DamageDealt> _damage = null!;

    public void OnStart(World world) => _damage = world.Events.Queue<DamageDealt>();

    public void Execute(World world, float deltaTime)
    {
        _damage.Raise(new DamageDealt(default, default, 0));
    }
}
```

`Queue<T>()` 不存在时创建；之后直接用。

## 6. 桥接到 `ReluctersteSDK.EventSystem`

Game 的事件是**帧内数据流**，不支持委托订阅、异步或继承分发。需要广播给 UI、存档、遥测时，在应用层桥接：

```csharp
using ReluctersteSDK.EventSystem;
using ReluctersteSDK.EventSystem.Interfaces;

public sealed class DiedEvent : EventBase
{
    public Entity Victim { get; init; }
}

public sealed class EventBridgeSystem : ISystem
{
    private readonly IEventBus _bus;
    public EventBridgeSystem(IEventBus bus) => _bus = bus;

    public void Execute(World world, float deltaTime)
    {
        foreach (ref readonly EntityDied e in world.Events.Read<EntityDied>())
            _ = _bus.PublishAsync(new DiedEvent { Victim = e.Victim });
    }
}
```

两个包没有代码依赖，桥接完全在应用层完成。

## 8. 明确不做的事

| 不做 | 原因 |
|---|---|
| 异步 / `Task` | 跨帧或跨线程交给外部总线 |
| `Subscribe` 委托订阅 | 需要定义执行顺序、重入与异常传播，等于再造一个总线 |
| 类型继承分发 | `Raise<Derived>` 只有 `Read<Derived>` 看得到 |
| 事件序列化 | 事件是“这一帧发生过什么”，不是状态 |

---

## 9. 常见陷阱

| 现象 | 原因 |
|---|---|
| 本帧读不到刚 Raise 的事件 | 单帧延迟是设计行为；Startup 阶段除外 |
| 读到的事件越读越乱 | 保存了 `Read` 的 span 跨帧使用；改用 `ReadList` 或复制 |
| 消费系统读到了空 | 消费系统在产生系统之前执行；调整优先级或接受一帧延迟 |
| `World.Clear()` 后事件消失 | `Clear` 会同时清读写缓冲 |
