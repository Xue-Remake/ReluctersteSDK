# 10 · 命令缓冲

**目标**：在 `Query.ForEach` 里安全地生成子弹、销毁敌人、挂接父子关系，并清楚每条命令在什么时机执行。

---

## 1. 为什么需要它

```csharp
world.Query<Health>().ForEach((Entity e, ref Health h) =>
{
    if (h.Value <= 0)
        world.Destroy(e);      // ❌ InvalidOperationException
});
```

`ForEach` 的驱动是组件存储的紧凑数组。遍历中途删除元素会触发 swap-remove，后面的下标与长度全部变化，继续遍历就是越界或漏读。

`CommandBuffer` 的做法：**先把操作记下来，等遍历结束再统一执行**。

```csharp
world.Query<Health>().ForEach((Entity e, ref Health h) =>
{
    if (h.Value <= 0)
        world.Commands.Destroy(e);   // ✅ 只登记
});
```

---

## 2. 回放时机

```
World.Update(dt)
├─ Events.Swap()
├─ Update 阶段
│   for each system:
│       system.Execute(world, dt)
│       Commands.Playback(world)      ← 每个系统后立即回放
├─ LateUpdate 阶段（同上）
└─ Commands.Playback(world)           ← 兜底：系统外写入的命令
```

`World.Render` 与 `Start` / `Shutdown` 也会在阶段结束后回放。

因此：

- **下一个系统能看到上一个系统的命令结果**；
- 在 UI 回调等系统外写入的命令，会在下一次 `Update` 末尾生效；
- 回放期间新登记的命令留到下一次回放，不会死循环。

---

## 3. 全部命令

```csharp
// 创建实体；回调里可以立刻挂组件
world.Commands.Create(e =>
{
    world.Add(e, Transform.Identity);
    world.Add(e, new Velocity { Value = new CartesianVector2D(0, -400) });
});

// 销毁（回放时实体已失效则跳过）
world.Commands.Destroy(enemy);

// 添加 / 移除组件（值拷贝；回放时实体已失效则跳过）
world.Commands.Add(e, new Health { Value = 100, Max = 100 });
world.Commands.Remove<Dead>(e);

// 层级
world.Commands.SetParent(child, parent);
world.Commands.RemoveParent(child);

// 单例
world.Commands.SetSingleton(new WaveState { Wave = 3 });
world.Commands.RemoveSingleton<WaveState>();

// 任意逻辑
world.Commands.Defer(w =>
{
    Console.WriteLine($"当前实体数 {w.EntityCount}");
});

// 合并另一个缓冲
world.Commands.Append(otherBuffer);

// 丢弃
world.Commands.Clear();
```

| 成员 | 说明 |
|---|---|
| `Count` / `IsEmpty` | 待执行命令数 |
| `Playback(world)` | 按登记顺序执行并清空；返回执行数量 |
| `Clear()` | 丢弃全部待执行命令 |

`Playback` 遇到异常会**继续执行其余命令**，最后抛 `AggregateException`。

## 4. 值拷贝陷阱

```csharp
var health = new Health { Value = 100 };
world.Commands.Add(e, health);
health.Value = 1;                 // 改的是局部变量
// 回放时用的仍是 100
```

`Add<T>` 捕获的是**登记时的值**。要传引用语义，用 `Defer`：

```csharp
world.Commands.Defer(w =>
{
    ref Health h = ref w.Get<Health>(e);
    h.Value = 1;
});
```

---

## 5. 顺序语义

命令严格按登记顺序执行，**没有优先级**：

```csharp
world.Commands.Destroy(e);
world.Commands.Add(e, new Health());   // ❌ 回放时 e 已失效，Add 被跳过
```

`Destroy` 之后的 `Add` / `Remove` 会被跳过（不抛异常），但 `Defer` 里的代码不会被跳过——它可能访问到失效实体。对同一实体先销毁再操作，顺序要自己保证。

---

## 6. 完整示例：一波敌人与清理

```csharp
using ReluctersteSDK.Game.Ecs;
using ReluctersteSDK.Math.Vectors;

public struct SpawnRequest { public int Count; }
public struct EnemyTag { }
public struct Dead { }
public struct Health { public int Value; public int Max; }

public sealed class WaveSystem : ISystem
{
    public void Execute(World world, float deltaTime)
    {
        // 1) 处理生成请求
        world.Query<SpawnRequest>().ForEach(
            (Entity e, ref SpawnRequest req) =>
            {
                for (int i = 0; i < req.Count; i++)
                {
                    int x = 100 + i * 60;

                    world.Commands.Create(spawned =>
                    {
                        world.Add(spawned, new Transform
                        {
                            LocalPosition = new CartesianVector2D(x, 0),
                            LocalScale = new CartesianVector2D(24, 24)
                        });
                        world.Add(spawned, new EnemyTag());
                        world.Add(spawned, new Health { Value = 30, Max = 30 });
                        world.Add(spawned, new Velocity
                        {
                            Value = new CartesianVector2D(0, 60)
                        });
                    });
                }

                world.Commands.Destroy(e);   // 请求实体用完即删
            });

        // 2) 清理死亡敌人
        world.Query<Health, EnemyTag>().ForEach(
            (Entity e, ref Health h, ref EnemyTag _) =>
            {
                if (h.Value <= 0)
                    world.Commands.Destroy(e);
            });
    }
}
```

`world.Commands.Create` 的回调在**回放时**执行，所以回调里调用 `world.Add` 是安全的：那时新实体已经创建。

## 7. 与 `ToEntityArray` 的取舍

| 方式 | 分配 | 适用 |
|---|---|---|
| `Commands` | 每条命令一个委托闭包 | 需要在系统内精确控制执行时机；结构修改多 |
| `ToEntityArray()` | 一次数组 | 一次性批量处理；结构修改少 |

```csharp
// 快照方式
Entity[] all = world.Query<Health>().ToEntityArray();
foreach (Entity e in all)
{
    if (world.IsAlive(e) && world.Get<Health>(e).Value <= 0)
        world.Destroy(e);
}
```

两种都合法。遍历规模大且修改多时，`Commands` 的闭包分配也值得注意；极端场景可以自己维护 `List<Entity>`。

## 8. 层级与单例的延迟操作

```csharp
// 生成一个挂在玩家身上的武器（父子关系必须等实体真正创建后建立）
world.Commands.Create(weapon =>
{
    world.Add(weapon, new Transform
    {
        LocalPosition = new CartesianVector2D(16, 0),
        LocalScale = CartesianVector2D.One
    });
    world.Add(weapon, new WeaponTag());

    world.Commands.SetParent(weapon, player);   // 回放期间登记，下一次回放执行
});
```

注意：在 `Create` 回调里再登记的命令会在**下一次** `Playback` 执行（`Playback` 先清空再执行快照）。如果要求同一批内完成，可以在 `Defer` 里直接调用 `world.SetParent`。

## 9. 常见问题

| 现象 | 原因 |
|---|---|
| 遍历还是抛异常 | 直接调用了 `world.Add/Destroy`；改成 `world.Commands.*` |
| 命令没生效 | 在系统外写入后没有触发 `Update` / `Render` / `Playback` |
| 生成出来的实体没有组件 | 在 `Create` 回调外给新实体加组件；那时实体还不存在 |
| 下一帧才看到新实体 | `Playback` 在系统之后；需要同系统内看到就手动 `Playback` |
